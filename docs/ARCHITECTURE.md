# MineMate architecture

MineMate is a single-node TypeScript application. Fastify serves the API, WebSocket
events and the Vite/React build. SQLite uses WAL, foreign keys and numbered,
transactional migrations. No external database or message broker is required.

## Domain boundaries

- `packages/shared`: Zod contracts, capabilities, lifecycle and permissions.
- `packages/database`: migrations and typed SQLite records; durable jobs and audit.
- `packages/docker`: Docker Engine API transport and ownership enforcement.
- `packages/minecraft`: Java/Bedrock adapters, readiness and diagnostics.
- `packages/settings-schema`: validated properties and revision-aware editing.
- `packages/backup`: safe archives, atomic directory swaps and retention.
- `packages/mod-platforms`: Modrinth/CurseForge adapters and dependency planning.
- `packages/gateway-protocol`: Java protocol framing and UDP relay.
- `packages/ui`: tokens, primitives, assets, motion and optional sound.
- `apps/api`: authenticated routes, orchestration, jobs, reconciliation and gateway.
- `apps/web`: bilingual first-run, worlds, wizard and graphical management.

Integrations are injected at boundaries. Tests substitute controlled providers;
production never substitutes simulated servers or fabricated metrics.

## Persistent data contract

`MINEMATE_DATA_PATH` is the application-visible root (default `/data` in Docker).
`MINEMATE_HOST_DATA_PATH` is its canonical absolute path on the Docker host.
These roots are different namespaces. Server creation requires a successful
host-bind sentinel check, not merely a string prefix. Immutable UUIDs address
`servers/<id>/{server,backups,snapshots,uploads,imports,metadata}`. Application
SQLite, configuration, encrypted secrets and logs reside under `app/`. Cache,
gateway, replaceable assets and temporary files have separate root directories.
User names never appear in filesystem paths. All filesystem operations reject
absolute paths, traversal, NULs and symlinks. Archives are validated in staging
with count, size and compression bounds before any live directory mutation.

## Database schema

Users (owner/admin/member), hashed sessions, per-server permission grants,
servers, configurations, runtime observations, EULA acceptances, operations,
installed content/source metadata, backups/targets, notifications, audit events,
settings and update records use UUIDs and UTC timestamps. A singleton bootstrap
claim makes the first-user transaction exclusive. Disabled users lose sessions.
The immutable owner cannot be disabled, demoted or deleted. Passwords use
Argon2id; random session tokens are stored only as SHA-256 digests.

## Docker ownership and security

Every managed server has `io.minemate.managed=true`, `io.minemate.server-id=<uuid>`,
`io.minemate.kind=minecraft-server` and an installation identity label. Every
operation re-inspects and verifies all labels before acting. Container creation
accepts a fixed configuration generated by the runtime adapter: no arbitrary
host bind, privileged flag, devices, host network, image or shell command.
RCON is internal only, uses random per-server secrets, and is never returned to
the browser. The daemon control endpoint is configured by the installer only.
Docker creation is host-equivalent authority; a proxy reduces accidental API
surface, not the consequences of a compromised privileged orchestrator.

Minecraft containers use a dedicated bridge. A protocol-aware gateway owns the
LAN ports so sleeping Java servers can answer status pings and wake on login.
UDP routes are per-client; cold-start Bedrock traffic triggers wake and clients
retry. The gateway never claims Bedrock ready based on TCP probes. Ports are
reserved transactionally and also checked against actual listeners and Docker
published ports. No RCON ports are published.

## API contracts

All routes use `/api/v1`. Public access is limited to health, bootstrap status,
first-admin registration and login. Every mutation checks Origin and a
session-bound CSRF token, and all server routes require the corresponding grant.
JSON bodies are validated by shared Zod schemas; files have bounded multipart
uploads. Long operations return durable operation IDs. Backend monitoring pushes
permission-filtered events through authenticated, same-origin WebSockets.
Clients refetch typed resources after invalidation; they do not independently
poll Docker. Errors have code, message and optional technical details.

## Lifecycle and recoverability

Desired state, Docker observation and Minecraft readiness are independent.
Operations are persisted before execution and locked per server. Startup
reconciles owned containers and marks interrupted operations with recovery
information. Container-running is not Minecraft-ready. Healthchecks and
protocol observations drive RUNNING. Backups stop the server for a consistent
snapshot (safe for both editions); restore and updates create recovery backups
before staging/atomic application. State and operation progress remain visible
after browser refresh. Crash loops have bounded retries and notifications.

## Visual system

Warm sky, grass, dirt, stone, water and portal tokens form a coherent landscape.
Semantic SVG assets are centralized and replaceable. Layered CSS voxel scenes,
bounded particles and spring motion communicate state without hiding exact
values. Shared accessible controls and focus-trapping dialogs serve both small
screens and desktop. Reduced motion/effects pause decoration. Sound is opt-in,
unlocked by a user gesture, and generated centrally with separate UI/ambient
volume. Every visible value comes from an API; empty installations have no fake
worlds. English/German translation keys are separate from components.

## Validation

Unit and API integration tests exercise security boundaries, migrations,
bootstrap races, isolation, archives, compatibility, jobs and rollback. A
controlled Docker fixture checks real Engine requests without Mojang access.
Playwright checks the first-run and management flows on desktop/mobile.
Actual Minecraft downloads and EULA acceptance are separate live acceptance
checks; test doubles never constitute evidence of Minecraft LAN connectivity.
